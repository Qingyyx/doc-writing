# 0005 报告层作为输出契约

- 状态：已接受
- 日期：2026-11-01

## 背景

文档交付时没有完成定义。长文与短文都叫"写完了"，读者无法判断作者是否跑过 P0、是否删过、结论句里的判断是观测还是推断。缺一个可观察的完成信号，写作过程就不可复查，失败也无法在下一份文档里被纠正。

第一版把体检表放在"文档之外"，实践中有两个问题：一是它经常被贴进文档末尾，读者拿到的是带作者批注的稿子；二是类型、读者、删减记录、证据等级都是写作过程的元信息，写进正文会破坏读者视角。

## 决策

一次交付分两层，去向固定。

| 层 | 内容 | 去向 |
|---|---|---|
| 文档层 | 正文与附录；一句话结论、证据、取舍 | `doc-<slug>.md`，或直接作为回答正文 |
| 报告层 | 7 行检查记录：类型、一句话结论、读者与决定、删减、证据强度、未验证、私有条件缺口 | 对话回复，不写入文档文件 |

报告层缺任何一行即未完成。字段定义见 [SKILL.md](../../SKILL.md) §7。

报告是检查记录，不是总结。它不复述文档内容，只报告四件事：判定了什么、删了什么、哪些断言没验证、哪些私有条件还没确认。下游可以按行名解析，人工可以逐行核对。

## 后果

文档层只对读者负责，元信息不污染正文。报告层保留可观察的完成信号，读者能快速判断可信度，维护者能按固定字段解析。写作多一步记录成本。

代价是报告层可能被填成形式：字段都在，数字是编的。处理方式是把可核对的部分留给人工评审：删减行要求写节数与段数，证据强度行要求计数，未验证行要求列出具体项。填表本身不证明删过，只提供可追问的线索。

## 备选方案

- 把 7 行全部写进文档末尾：读者拿到带批注的稿子，元信息混装，等于违反一文件一类型。
- 让模型自评"已完成"：自评不可观察，无法区分跑过流程与觉得跑过流程。
- 只报字数与页数：数字不证明删过承重节以外的内容，也不说明结论强度。
- 把报告层写成总结：总结复述内容，读者读不到删减与未验证项，完成信号消失。
- 用固定模板正文取代报告层：模板可以被不执行而填写，与六段模板同一失效模式。
