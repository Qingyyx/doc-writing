# 0006 结构物先于细节

- 状态：已接受
- 日期：2026-11-01

## 背景

第一版把"结论前置"作为结构闸的唯一要求：首段一句话结论，其余按断言展开。实际使用中出现了新的失败：文档变短了，结论也清楚，但读者读完建立不了整体模型。读者知道作者主张什么，却说不清"这东西由哪几部分组成、主路径怎么走、某个细节属于哪一块"。

问题不在详略。细节再少，如果没有一个挂载点，读者也只能线性记住一串段落，无法在脑中组织它们。结论解决"作者主张什么"，不解决"读者如何定位"。

## 决策

结构闸从两段扩展为三层。

| 层 | 内容 |
|---|---|
| 第 1 段 | 一句话结论：对象、判断、条件 |
| 第 2 段 | 结构物：组件图、分层表或主路径链，写清部件与连接 |
| 细节节 | 每节标题对应结构物上的一个节点，首句挂回该节点 |

结构物按关系选：分层用部件表，时序用主路径链，依赖用依赖图。判据是双向的：每个节点要有一个细节节，每个细节节要能指回一个节点。

同时增加理解门，三条自检：能复述整体结构、能定位任一细节节、能回答一个文档没直接写的场景。第三条区分"读过"与"理解"。

解释文档的结构从"现象 → 机制 → 边界"改为"结构 → 主路径 → 边界与例外"，与三层对齐。

## 后果

文档多一段结构物，篇幅略增。读者获得一个可复用的定位框架，后续细节不必重新建立上下文。结构物与目录必须同步，否则两向判据对不上。理解门是自检，不是自动判定，仍由人工评审确认。

## 备选方案

- **只加一段概述**：概述复述全篇，读者仍然拿不到部件与连接，等于把目录写成了散文。
- **只给目录**：目录是名称，不是关系。读者知道有哪些节，不知道它们如何连接。
- **把结构图放附录**：正文读的时候缺参照，读者要到附录才能定位，等于没有。
- **要求每节先写小结**：小结只复述本节，不提供上层定位，反而增加篇幅。
