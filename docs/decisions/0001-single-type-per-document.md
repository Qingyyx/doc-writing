# 0001 一文件一类型

- 状态：已接受
- 日期：2026-11-01

## 背景

AI 写出的长文里，教学、决策、参考、解释四种语气经常出现在同一份文件。读者会被迫跳过与自己无关的大段内容，承重结论被背景与细节稀释。症状在上层表现为"太长"，实际成因是这份文件同时要满足多类读者。

模板清单式方案把这个问题当成"节数不够规范"，于是继续补小节。补得越多，一份文件承载的意图越多，混装越严重。

## 决策

一个文件只承载一种文档类型。类型由读者的动作判定：要选方案是决策文档，要判断形势是证据文档，要照着做是操作文档，要查条目是参考文档，要理解机制是解释文档。判定结果由 P0 探针产生，入口状态固定为「未判」。

出现两种以上类型时，拆成两份文件，或删掉非主类型的部分。标题写着"方案"但读者要照着做，它按操作文档处理。判据见 [SKILL.md](../../SKILL.md) §1、§2。

## 后果

一份文件可以为多类读者服务，改为多份文件各服务一类读者。文档数量增加，单份长度下降，每份都有明确的完成条件。

代价是拆分会带来维护成本：同一事实可能在两份文件里各出现一次。处理方式是主文档写事实，另一份只链接，不复述。拆分前先确认两类读者是否真的需要各自的文件；只有一类读者时，拆开只是把一篇长文切成两篇。

## 备选方案

- 一份文件分节标类型：读者仍需在文件内跳读，长度不变，混装只是换了一个可见的标签。
- 用目录给每节打类型标签：标签不改变内容，承重节仍被无关章节稀释；标签还会让读者以为已经分离。
- 一个万能模板适配所有文档：模板越完整，覆盖的冲动越强，"每节都留"更难拒绝，正是症状来源。
- 按章节数量上限控制：节数限制不区分承重节与背景节，作者会合并小节而不是删除内容。
