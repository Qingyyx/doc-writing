# 0002 结论前置

- 状态：已接受
- 日期：2026-11-01

## 背景

默认的写作顺序是背景、过程、分析、建议，判断出现在正文末尾。读者必须读完全文才知道作者要自己决定什么。决策者通常只读前两屏，于是文档的实际作用是"看起来写了很多"，不是"促成决定"。

常见的补救是把摘要放到最前。摘要复述全篇，换一个主题照样成立，读者读完摘要仍然不知道该同意还是反对。

## 决策

第一段写一句话结论，含对象、判断、条件，且必须可被反驳。每个二级标题是一个名词短语或一个判断，每节首句是该节的断言，每节末尾不复述小结。

写作顺序因此反过来：先定结论，再决定哪些节支撑它，最后才写正文。骨架不过（首段没有可反驳的判断，或某节首句不是断言）不展开正文。判据见 [SKILL.md](../../SKILL.md) §3。

## 后果

读者在前两屏就能判断要不要继续读，也能直接反驳结论。作者必须在动笔前想清楚判断，不能靠写完再总结。

代价是先想结论比先铺背景难，作者在没有结论时容易拖延。处理方式是允许结论写成"当前证据不足以判断，需要 X"，这仍然是一句话结论，仍然可被反驳。

## 备选方案

- 摘要前置：摘要复述全篇，不承诺判断，读者读完仍不知道要决定什么；它还可以套用到任意主题。
- 结论放节末：读者要读完才看到判断，与默认写法的失败模式相同，只是位置从全文末尾挪到节末。
- 只写执行摘要：执行摘要可以不含可反驳的判断，也不要求对象与条件，读者无法据此反对。
- 结论与建议合并：建议是祈使句，结论是判断句；合并后读者分不清哪些是事实、哪些是要他做的事。
