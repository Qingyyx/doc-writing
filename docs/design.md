# 设计：为什么这样设计

> 本文件回答"为什么这样设计"。运行时规则、五类文档的门禁表、删减闸与 AI 味六项只在 [SKILL.md](../SKILL.md)；门禁的检查方式在 [verification.md](verification.md)；术语定义在 [glossary.md](glossary.md)。三处都不复述入口内容。

## 问题：四个症状与一条因果链

AI 文档的毛病不是文笔差，是四个可观察的症状反复出现：

| 症状 | 读者的感受 | 可观察量 |
|---|---|---|
| 过长 | 读到承重结论之前，已经读了数倍于需要的页数 | 正文页数 ÷ 读者预算 |
| 混装 | 同一份文件里要跳过大段与自己无关的内容 | 一个文件里出现的文档类型数 |
| 结论埋没 | 读完才知道作者要读者决定什么 | 一句话结论出现的位置 |
| AI 味 | 每段都像能删，删了结论也不变 | 可删段落占全篇的比例 |

四个症状由同一条因果链产生。每一步都由上一步直接推出，不需要作者犯错，只需要作者按默认习惯写：

| # | 环节 | 机制 | 后果 | 症状 |
|---|---|---|---|---|
| 1 | 从内容清单开始写 | 先问"要覆盖哪些内容"，不问"读者要做哪个决定" | 文档没有买主，长度由素材量决定 | 过长 |
| 2 | 一个文件服务多类读者 | 教学、决策、参考、解释的语气写在同一份文件里 | 每类读者都要跳过与己无关的段落 | 混装 |
| 3 | 用覆盖代替取舍 | 每节都留，理由是"以后可能有用" | 承重节被背景与细节稀释 | 过长 |
| 4 | 结论产生在正文之后 | 先写背景与过程，最后才给判断 | 判断落在中段，读者读完才知道要决定什么 | 结论埋没 |
| 5 | 断言不标强度 | 观测、推断、叙事用同一种语气 | 叙事级判断被当成事实写进结论句 | AI 味 |
| 6 | 删减没有判据 | "再改得好一点"不可执行 | 篇幅只增不减 | 过长、AI 味 |
| 7 | 完成不可观察 | 长文与短文都叫"写完了" | 失败没有信号，下一份文档回到第 1 步 | 四者 |

这条链自我强化。第 1 步不设读者，第 3 步就永远有理由保留每一节；第 6 步没有判据，第 7 步就没有失败信号，于是下一次仍然从第 1 步开始。方法要切断的是链，不是修某一句措辞。

## 五条设计原则

| 原则 | 切断的环节 | 落点 |
|---|---|---|
| 目的先于文本 | 1、3 | 入口固定为「未判」；P0 三问，上限 10 分钟，答不上来不写正文 |
| 一文件一类型 | 2 | 五类文档五道门禁；类型挂在读者动作上，不挂在标题上 |
| 结论前置，骨架先定 | 4 | 首段一句话结论；骨架不过不展开正文 |
| 删减为主动作 | 3、6 | 五个可观察判据；AI 味六项各给失败签名 |
| 输出可检查 | 5、7 | 证据三级只用于判定，文档用来源与措辞承载；报告层逐行填，缺行即未完成 |

五条不是并列清单。目的原则解决"为谁写"，类型原则解决"混装"，结构原则解决"结论埋没"，删减原则解决"只增不减"，可检查原则解决"失败无信号"。

## 三闸结构

```
入口（未判）
  → 目的闸：读者是谁 + 读完做哪个决定（P0 三问，≤10 分钟）
      → 判不出类型 → 停在未判，只交 P0 结果
      → 判出类型 → 结构闸：单类型 + 一句话结论 + 骨架
          → 骨架不过 → 不展开正文
          → 骨架通过 → 写正文 → 删减闸：删节测试 + 重复 + 密度 + 长度预算 + 混装
              → AI 味六项 → 文档交付 + 报告层检查记录（7 行）
```

| 闸 | 输入 | 产物 | 失败表现 |
|---|---|---|---|
| 目的闸 | 用户请求与现有材料 | 读者、决定、一句话结论 | 没跑 P0 就选模板 |
| 结构闸 | 类型与结论 | 骨架表，每节一个断言 | 先写正文，后补结论 |
| 删减闸 | 完成稿 | 删减记录与报告层检查记录 | 只交稿，不记录删了什么 |

逐条判据见 [SKILL.md](../SKILL.md) §1、§3、§4、§5。本文件只说明三闸为何按这个顺序排列：前一道闸的产物是后一道闸的输入，跳过任何一道，后面的检查都失去对象。

## 与"写作模板清单"式方案的差异

模板清单式方案给一张覆盖全部小节的表，作者按表填写，读者按表阅读。

| 维度 | 模板清单式方案 | 本方法 |
|---|---|---|
| 入口 | 先选模板，再往里填 | 先跑 P0，类型是探针的输出 |
| 覆盖 | 模板列满所有可能小节 | 每节先答"删了它读者会做错什么" |
| 结论 | 摘要放最前，复述全篇 | 一句话结论，含对象、判断、条件 |
| 类型 | 一个模板适配所有文档 | 一文件一类型，五道门禁 |
| 删减 | 换一种说法再改一遍 | 五个可观察判据，逐项执行 |
| 质检 | 凭感觉判断写得好不好 | 报告层逐行填，gate 检查形态 |
| 失败信号 | 无 | 每节、每项都有失败签名 |

模板清单式方案的第 1 步就是选模板，它把"这份文档要为谁服务"这个判断压缩成一个选项。模板越完整，覆盖的冲动越强，第 3 步的"以后可能有用"就越难拒绝。本方法把模板换成探针，把清单换成门槛。

## 非目标

| 非目标 | 原因 | 边界 |
|---|---|---|
| 不判断内容是否正确 | 事实正确性由来源与作者负责 | 本方法给证据分级，不给事实核查 |
| 不做排版与格式转换 | 标题层级、样式、转换由工具完成 | 本方法不产出样式与格式 |
| 不把普通提问当文档任务 | 只问"怎么写更好"且没给材料时，直接回答即可 | 用户点名本方法，或给出会写坏的具体材料时才走三闸 |
| 不保证文档被采纳 | 采纳取决于组织与决策权 | 本方法只保证决策者能读完并作出判断 |

## 有效性证据

设计依据来自四个外部来源，它们支撑的是取舍，不是效果承诺：

| 来源 | 支撑的取舍 |
|---|---|
| diataxis.fr | 文档按读者用途分型，不同类型不能共用一套结构 |
| Malte Ubl《Design Docs at Google》(2020) | 决策文档的长度预算：mini 版 1 到 3 页，完整版 10 到 20 页 |
| Google Technical Writing One | 结论前置、一句一断言、删减冗余的具体做法 |
| Shaib et al., 2026, arXiv:2509.19163 | AI 低质文本的维度划分：信息效用、信息质量、风格质量 |

本版本没有行为用例的运行记录。可检查的证据只有两项：报告层的检查记录把"是否删过、删了几节"变成可观察量，gate 把入口形态变成可检查项。[evals/cases.yaml](../evals/cases.yaml) 目前是用例模板，填充与运行由维护者完成，结果不进入本文件。
