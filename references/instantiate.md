# 私有条件盘点
> 何时读我：通用模板写完了，但不知道这份文档的读者、组织和合规条件会把哪一节改掉。

私有条件指：不在通用模板里、由这份文档的具体处境决定、且会翻转结构的条件。本文件把 SKILL.md §6 的五条逐条展开为可执行盘点，并给缺信息时的写法。

## 盘点表怎么填

交付前先落一张空表，五行全填，不留空行。

| 条件 | 取值 | 影响哪一节 | 缺口写法 |
|---|---|---|---|
| 读者是否有决策权 | 有 / 无 / 未知 | 见下 | 见下 |
| 是否跨团队或跨语言 | 是 / 否 / 未知 | | |
| 是否会被半年后回溯 | 是 / 否 / 未知 | | |
| 是否涉及安全 / 隐私 / 合规评审 | 是 / 否 / 未知 | | |
| 文档是否会持续迭代 | 是 / 否 / 未知 | | |

"未知"是合法取值，它直接进报告层的私有条件缺口行。

## 条件 1：读者是否有决策权

| 项 | 内容 |
|---|---|
| 怎么判断取值 | 问"这份文档发出去，谁能签字"。能签的是读者本人则 有；要转呈则 无 |
| 有 → 改哪一节 | 结论句用祈使或判断；取舍节给到一个推荐方案 |
| 无 → 改哪一节 | 结论改为"选项 + 建议 + 需要谁批"，结论句不能是祈使句；补一节"需要谁批" |
| 缺信息时 | 写"无法判定决策权：未确认 <角色> 是否签字，结论先按无决策权写" |

无决策权时最常见的错是把建议写成命令。命令句会让转呈人无法加工。

## 条件 2：是否跨团队或跨语言

| 项 | 内容 |
|---|---|
| 怎么判断取值 | 看读者名单里是否有非本团队的人，或是否有非中文母语读者 |
| 是（跨团队）→ 改哪一节 | 首段前补术语表，篇幅上限 +1 页；取舍节补一句"本团队视角" |
| 是（跨语言）→ 改哪一节 | 术语首次出现给英文原词；参考文档的条目名保留英文 |
| 缺信息时 | 写"读者名单未定，术语表按最坏情况预留 1 页" |

术语表只放会改变理解的名词，不放下定义也能读懂的量词与时态。

## 条件 3：是否会被半年后回溯

| 项 | 内容 |
|---|---|
| 怎么判断取值 | 问"半年后有人要照这份文档判断当时为什么这么定吗" |
| 是 → 改哪一节 | 文档头补三行：日期、版本、失效条件；证据节补来源时点 |
| 否 → 改哪一节 | 不补三行，删掉所有"截至本文写作时"类限定 |
| 缺信息时 | 写"回溯需求未定，按会回溯处理，三行先补齐" |

失效条件要写成可观测的句子，例如"P99 连续一周低于 50ms 时本结论失效"，不写"情况变化时"。

## 条件 4：是否涉及安全 / 隐私 / 合规评审

| 项 | 内容 |
|---|---|
| 怎么判断取值 | 看改动是否触及用户数据、权限、对外接口、审计留痕 |
| 是 → 改哪一节 | 跨切面独立成节，写威胁、数据流向、留痕与审批人；不得并入正文 |
| 否 → 改哪一节 | 不设跨切面节，在取舍节写一句"无安全 / 隐私 / 合规影响" |
| 缺信息时 | 写"合规影响未判，跨切面按需评审处理，需 <团队> 确认" |

涉合规时，评审结论要写"谁在什么时候批的"，不写"已通过评审"。

## 条件 5：文档是否会持续迭代

| 项 | 内容 |
|---|---|
| 怎么判断取值 | 问"这份文档三个月后还会被改吗，改的时候读者要知道改了什么吗" |
| 是 → 改哪一节 | 决策记录与实现状态分开写：决策节冻结，实现状态另起一节带日期 |
| 否 → 改哪一节 | 合成一份，不设状态节，删除版本号 |
| 缺信息时 | 写"迭代频率未知，决策与状态先分开写，合并成本低于拆分" |

分开写时，决策节只追加不修改。要改决策，新开一条记录并注明替代了哪条。

## 缺口的写法

| 不合格 | 合格 |
|---|---|
| "读者情况待确认" | "无法判定决策权：未确认架构组是否有签字权，需问 <姓名> 的 <事项>" |
| "合规影响待评估" | "无法判定合规影响：涉及手机号明文存储，需安全团队在评审会前确认" |
| "迭代计划未定" | "无法判定迭代频率：需求方未定 Q3 是否继续投入，按会迭代处理" |

合格写法三件套：判定不了哪个条件、缺的是谁的什么信息、暂时按哪个取值写。三件缺一，缺口行不成立。
